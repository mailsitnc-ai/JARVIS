On 2026-09-14 the JARVIS panel got an Iron-Man arc-reactor look. `ui/reactor.py` is an `ArcReactor(tk.Canvas)`: faked glow via stacked concentric ovals, a rotating 10-segment coil ring, a pulsing core, a faint triangle. States via `set_state`: offline/idle/busy/speaking/error (palette + spin + pulse in `STATES`). Animates `after(66ms)` when visible, throttled to 400ms / skipped when hidden (`set_visible`). `ui/panel.py` drives it: idle after boot, busy on submit, speaking (2.5s) on a `speak` reply, error flash. Palette C darkened (`bg #05070d`).

Reactor FINAL (2026-09-15): fully code-rendered, NO image assets at all (user was adamant: "i dont want rotating pngs, code it out, actual movement"). `ui/reactor_render.py` `render(size, deg)` draws each frame from geometry with numpy+Pillow: a STATIC tangled mesh sphere (chords between ~150 sphere points, 5 nearest neighbours) + STATIC white-hot core with radiating rays, and bold RINGS that orbit in REAL 3D (ellipses re-projected per `deg` about a yaw axis - not a 2D bitmap spin) + debris sparks; additive glow (blur via fixed-scale 8-bit copy) + exposure tone-map `1-exp(-field*0.5)` + blue ramp + edge vignette; supersample 1.3x then downscale = crisp. `ui/reactor.py` renders `_NFRAMES=24` frames at `_BASE=560` in a BACKGROUND THREAD at startup (~1.5s/frame, ~30s total; shows a fallback pulsing glow until ready), keeps them as in-memory PIL frames (never saved to disk), resizes to fit + cycles as PhotoImages, spin speed per state. Fallback glow if Pillow/numpy missing. To retune: run `python ui/reactor_render.py` (writes preview.png + preview9.png at deg 0/90 to check sphere-static/rings-orbit). Superseded the earlier baked-PNG approach below.

--- earlier (superseded): the reactor is NO LONGER a Tk-drawn arc reactor or a rotating PNG. It is a CODE-GENERATED particle plasma sphere baked to frames. `scratchpad bake_code.py` renders it with numpy+Pillow: ~13 orbital particle STREAMS at RANDOM orientations (not a lat/long grid - a clean grid looked like a "globe/atom" which the user rejected) + volumetric haze + shell + sparks, all as granular additive point splats; a STATIC white-hot core with rays (does NOT spin); glow via blur through a fixed-scale 8-bit copy (PIL can't GaussianBlur 'F' mode); exposure tone-map `1-exp(-field*0.55)` so dim haze glows and core saturates white; blue colour ramp; edge vignette to fade the square boundary. Baked into `ui/reactor_frames/frame_00..35.png` (36 frames, the sphere rotated per frame, core fixed). `ui/reactor.py` just loads the frames and cycles them (resized to fit, cached per size), spin speed per state (STATES step), fallback glow if Pillow/frames missing. Resolution-independent/crisp - re-bake at any size. To retune, edit bake_code.py (preview mode = one frame) then bake into ui/reactor_frames and restart the daemon. Needs Pillow+numpy (installed --user). KEY history: user wanted EXACTLY the reference (a blue energy sphere, file was Desktop/JARVIS ui.png at 118px - too low-res to upscale). Procedural clean rings = "looks like an atom"; rotating the PNG = "low res + whole thing spins". Winner = code-generated granular particle sphere.
