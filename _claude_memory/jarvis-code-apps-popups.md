Added 2026-09-15 (user asked "can it write code, make apps, and make pop ups"). Answer: yes, all three now work.

**Popups**: new `notify` capability in `core/permissions.py` CAPABILITIES; broker method `ActionBroker.notify(message, title="JARVIS")` in `core/actions.py` spawns a DETACHED PowerShell `System.Windows.Forms.MessageBox` via `subprocess.Popen` (non-blocking, survives a one-shot CLI exit; a daemon thread / ctypes MessageBox would die when `jarvis ask` exits). Dry-run returns a placeholder. Builtin skill `skills/popup.py` (triggers: popup / message box / show alert / alert|notify me) extracts the message and calls `context["actions"].notify`. Documented in `evolution_engine/prompts.py` DRAFT_PROMPT so evolved skills can use it.

**Writing code / making apps**: builtin skill `skills/write_file.py`. Parses the target path (`_target_path`: "as/named/called <file.ext>", folder from "to/in my desktop|documents|downloads" or a full path, defaults to Desktop), has the model generate the file contents (`context["llm"]`, system prompt = raw contents only), strips markdown fences (`_FENCE`), writes via `context["actions"].write_file` (gated `write_files`), and if the request says open/run/launch it also `open_path`s the file. Handles code, scripts, GUI apps (tkinter .pyw), html. `understand.py` got a system line + two examples so "write X and save it as Y (and open it)" stays ONE act step and is never turned into "open Notepad and type".

Browser fix (2026-09-16, user: "opens Edge instead of my existing Chrome"): root cause = `open_url` used `webbrowser.open` = OS default (Edge). Now `ActionBroker(browser=...)` + `_browser_exe()` resolves the preferred browser (chrome/edge/firefox/brave/path via which/App Paths) and `open_url` `subprocess.Popen([exe, url])` (launching chrome.exe with a URL reuses the existing Chrome window as a new tab); falls back to webbrowser.open if not found or browser="default". Config `window.browser` default "chrome". Orchestrator `_context` passes it. browser_tab/web_search route through open_url so all fixed. Tests pin `window.browser=default` (or mock Popen) to stay mockable.

Doc-writing routing (2026-09-16): deleted buggy evolved `generate_research_doc` (wrote to a literal "the desktop" folder). `write_file` triggers now include document/doc/note/report/essay/paper/letter/story + "titled", and `_target_path` maps "a document titled RESEARCH PAPER" -> "RESEARCH PAPER.txt" (default .txt); folder regex already resolves "to the desktop"->Desktop. Apps-actually-work fixes (2026-09-16, user: "the py apps it makes most of them dont work"): write_file now VERIFIES generated Python before saving via `_verify_python` - ast.parse syntax check with an LLM repair loop (up to 3), and scans imports (ast) for non-stdlib modules missing per `importlib.util.find_spec`, auto-installing them via `context["actions"].install_package` (MODULE_TO_PIP map). `_target_path` now picks the CODE file when a request names several ("save qr as hello.png ... save script as makeqr.py" -> makeqr.py) via `_CODE_EXT`. New broker `ActionBroker.run_python(path)` (gated run_command) actually RUNS the file: .pyw via pythonw (CREATE_NEW_PROCESS_GROUP, no console), .py in a fresh console (CREATE_NEW_CONSOLE) - because os.startfile just opened an editor. write_file's "run/open it" and open_last now use run_python for .py/.pyw (open_app still open_path=edit for "open X.py"). Apps really run now (2026-09-17, user: "most apps jarvis writes fail when I open them" -> "delete the skill and remake it no faults"). Root cause: `_verify_python` only checked syntax+imports, never RAN the code, so NameError/AttributeError/bad-call/missing-package only surfaced on open (and the CREATE_NEW_CONSOLE window closed before the traceback was readable). Rebuilt `skills/write_file.py` (commit `0844815`, version 2): after syntax-fix + package install, it SMOKE-RUNS the generated file in a subprocess (`_smoke_run`, feeds blank stdin, timeout 6s / 3s for GUI detected via `_GUI`). Classification: returncode 0 or TimeoutExpired (GUI/loop still alive) = OK; a **structural** exception at startup (ModuleNotFound/Import/Name/Attribute/Indentation/Syntax/Tab/UnboundLocal) = failure -> feed traceback back to the model, rewrite, re-test (bounded 4 attempts); non-structural errors (ValueError/EOFError from the blank input) are tolerated so interactive input() apps aren't wrongly "fixed". Reply notes "verified it runs" / lists installs / "still errors on start ...". Stronger generation system prompt (complete/runnable, no placeholders, GUI=tkinter, guarded `__main__`). Smoke-run confirmed: valid ok, NameError/ImportError/SyntaxError caught, interactive tolerated.

Fixing existing apps (2026-09-17, user: "most apps it makes fail; use the weather/time app to fix its ability to fix code"). Shared machinery extracted to `core/pyverify.py` (SYSTEM, GUI, STRUCTURAL, unfence, install_missing, smoke_run, verify_python) - imported by BOTH write_file and fix_code. NOTE: os.startfile opens .py by file association (may open an editor rather than RUN it); a GUI app saved as .pyw runs on open. Verified live: "open frenchjokes.py" -> opens the Desktop file.
